# S09–S13. Основа и стратегия ИИ

[Карта этапов](../ROADMAP.md) · [Каталог правил](ai-patterns.md).
Цель — много сочетаемых поведений с понятными причинами выбора и честной информацией.

## Контракт решений

Наблюдение S06 → память → стратегия → задачи и отряды → правила юнитов → команды S02.
Планировщик получает снимок знаний стороны и её ресурсов, не глобальные хранилища
врага. Память, планы, резервы и случайный выбор изолированы по ID участника S01a.
ИИ рассматривает всех известных врагов, а не единственного «другого игрока».
Полный мир доступен исполнителю для применения правил, но не для подсказки ИИ.

Правило — отдельная функция/небольшой модуль: стабильный ID, допустимые типы,
условия, оценка полезности, предлагаемые действия, причина, условие завершения.
Конфигурация содержит веса и пороги, а не код поведения в строках.
Добавление правила не требует новой ветки в общем цикле хода; регистрация и сценарий
должны быть достаточны. Полноценный язык сценариев или редактор правил не нужен.

Задача хранит цель, приоритет, исполнителей, резерв ресурсов/мест, прогресс,
срок пересмотра и причину отмены. Общие действия — идти, атаковать, строить,
нанимать, назначать, ремонтировать, исследовать, ждать — переиспользуются правилами.

## S09. Первый честный противник

Зависимости: S03, S06, S08. Ориентир: `app/game/ai/aiTurn.ts`; координация в `app`,
правила в отдельном срезе `features/ai`, знания/состояние в нижних слоях.

- Построить цикл с ограничением числа команд: наблюдение → выбор задачи → команда
  → обновление наблюдения → проверка исхода. Не эмулировать клики интерфейса.
- Первая цепочка: найти ресурсы → запустить добычу → казармы → нанять мечников →
  разведать противника → атаковать. При видимой угрозе защищать ратушу.
- Целью может быть граница разведки; координаты вражеской базы из генератора
  не использовать. Не найден враг — продолжить поиск, а не бесконечно ждать.
- Ограничить повторы неудачной команды; при отсутствии законного действия
  завершить ход с причиной. Между порциями работы отдавать управление браузеру.
- Уже в S09 писать структурированные записи решений с ID участника/партии/хода;
  просмотр и оценки альтернатив дополнить в S10.
- Идентификатор партии/хода отменяет старый запуск после сброса/загрузки/конца игры.
  Одинаковый сид принятия решений даёт одинаковое разрешение равных оценок.

**Подсказки:** начни с одной короткой цепочки решений на маленькой известной сцене,
затем убери лишнюю информацию. Сравни выбор одной команды с коротким планом;
последний потребует повторной проверки после каждого изменения мира.
**Unit-тесты:** нет законных действий, повтор отказа, предел команд, отменённый
ID партии и одинаковый выбор при одинаковом наблюдении/сиде; без реальных задержек.

**Готово:** ИИ сам развивает базу, находит игрока и способен разрушить его ратушу;
игрок может остановить ИИ и победить. Выполнены обе партии/сценария, без полного обзора.

## S10. Стратегия и оценка решений

Зависимости: S09.

- Ввести оценку потребностей: запас/доход ресурсов, население, выпуск войск,
  известная угроза базе, соотношение сил, качество разведки, готовность армии.
- Реализовать стратегические правила G01–G12 из каталога. На первом проходе
  снабдить существующими действиями; новые войска и исследования подключить позже.
- Срочная угроза ратуше прерывает мирные планы. Обычная смена стратегии требует
  заметного преимущества оценки и минимального срока удержания плана.
- Устаревшие контакты дают оценку риска, не точное знание. Недостаток информации
  повышает приоритет разведки; отсутствие контакта не доказывает отсутствие армии.
- Использовать общий механизм событий S02 для S09–S10; не заводить отдельное
  хранилище решений. Запись/её отключение не влияет на результат расчёта ИИ.

- Журнал разработчика: ход, ID правила, наблюдённые основания, оценки альтернатив,
  выбранная цель, результат команды. Игрок не получает скрытые причины/координаты.

- Подключить журнал к панели отладки S02a: фильтры по ИИ-участнику, ходу,
  юниту/задаче и ID правила. В партии с несколькими ИИ записи не смешиваются.
- В записи показывать стратегию, выбранное действие/цель, наблюдённые основания,
  оценки рассмотренных альтернатив и причины отказа, результат команды,
  перепланирование либо причину завершения хода. Это фактические данные
  планировщика, а не придуманное задним числом объяснение.
- Хранить ограниченное число записей; очистка журнала не меняет игру и память ИИ.
  Полные записи доступны в режиме отладки, обычный игровой журнал не получает
  скрытых сведений. Выключение панели не изменяет выбор действий.
- Проверить, что решения двух ИИ можно разобрать независимо даже после гибели
  цели: запись содержит снимок оснований на момент выбора, а не ссылки
  только на текущее состояние объектов.

**Подсказки:** сравни несколько характерных ситуаций на бумаге до настройки весов.
Рассмотри аварийный приоритет отдельно от обычной полезности; для устойчивости
выбора сравни штраф смены плана с минимальным сроком его удержания.
**Unit-тесты:** тревога перекрывает экономику, слабое изменение не меняет план,
устаревший контакт уменьшает уверенность, равные оценки разрешаются воспроизводимо.

**Проверка журнала:** фильтрация по двум ИИ, выбранное/отклонённое действие,
лимит записей, скрытые сведения вне обычного UI, одинаковые решения с включённым
и выключенным логированием при одинаковых знаниях и настройках.

**Готово:** одинаковые наблюдения воспроизводят решение; смена ситуации меняет
стратегию объяснимо, без переключений экономика/атака каждый ход.

## S11. Задачи экономики, разведки и строительства

Зависимости: S10.

- Назначать задачи с резервированием ресурсов, рабочих мест, клеток стройки,
  маршрутов выхода и ролей юнитов: один исполнитель не получает два задания.
- Выбирать ресурс по дефициту ближайших запланированных трат и текущему доходу.
  Не строить дополнительные шахты, если некому работать или нечем защитить подход.
- Оценивать известные площадки: доход, расстояние, угроза, связность, выходы найма,
  доступ к ресурсу. Перед постройкой повторно проверять маршрут на известной карте.
- Назначать разведку разных границ, проверку старых контактов и поиск ресурсов;
  избегать дублирования целей. Неизвестный тупик — повод сменить маршрут.
- Восстанавливаться после гибели рабочего/утраты здания; задачи отменяются и
  освобождают резервы. Снос собственной преграды допустим как последний выход.

**Подсказки:** отдельно оцени пригодность задачи и выбор исполнителя. Рассмотри
простое назначение по приоритету прежде сложной оптимизации; сравни результат
при двух рабочих, одном рабочем месте и конкурирующих расходах.
**Unit-тесты:** взаимное исключение назначений, освобождение резерва после отмены,
смена дефицитного ресурса, отклонение опасной/перекрывающей маршрут площадки.

**Готово:** выполняются W01–W10; нехватка дерева вызывает добычу дерева,
два рабочих не строят одно и то же и не блокируют единственный выход.

## S12. Тактика исходных юнитов и башен

Зависимости: S10–S11.

- Реализовать M01–M06, A01–A07, T01–T05 и согласовать их с рабочими задачами.
- Оценивать клетки по известным угрозам и доступным очкам, цели — по возможности
  уничтожения, роли и опасности. Не выбирать цель только по минимальному HP.
- Лучник сначала выбирает безопасную огневую клетку, потом стреляет; после атаки
  не отступает в том же ходу, поскольку это запрещено общей механикой.
- После каждой команды пересматривать локальную ситуацию: цель могла погибнуть,
  путь освободиться или появиться новый враг. Не исполнять устаревший список вслепую.

**Подсказки:** отдели законность действия от его тактической ценности. Для выбора
клетки оцени небольшой набор доступных позиций; сравни угрозу в момент хода
с угрозой ответного хода врага, не используя его скрытые объекты.
**Unit-тесты:** каждому M/A/T-ID — срабатывание и отказ; выбор цели с учётом
уже назначенного урона, отход вместо выстрела и запрет движения после атаки.

**Готово:** каждый ID исходной тактики имеет сценарий срабатывания и отказа;
оборона рабочих и фокус огня не требуют незаконных дополнительных действий.

### Расчистка и новая местность: приёмка S12

ИИ оценивает холмы/болота по общей стоимости движения и правилам обзора.
Если рабочему разрешена расчистка S01/S08, он использует её для полезного прохода
по известной карте, сравнивая затраты с обходом и потребностью в дереве.
**Проверки/готово:** полезная расчистка, выгодный обход, отказ при угрозе/нехватке
действий, сохранение подходов к добыче; скрытые деревья не становятся целями.

## S13. Отряды и операции

Зависимости: S12.

- Хранить ударную группу, гарнизон и разведку; юнит состоит только в одном задании.
  Пункты сбора выбираются по известной безопасной и доступной области.
- Переходы операции: сбор → движение → контакт/бой → преследование либо отход →
  перегруппировка. Готовность учитывает состав, HP, отставших и оценку противника.
- Ограничить ожидание сбора: по тайм-ауту переоценить цель/состав, а не отправлять
  по одному и не копить армию навсегда. Рейд допускает меньшую группу по своей цели.
- При угрозе базе выделить достаточную защиту и оценить отзыв армии; не отзывать
  всех из-за одного слабого контакта. При серьёзной угрозе прервать наступление.
- Обход занятой клетки, уступка прохода, временный резерв позиции; при отсутствии
  прогресса несколько ходов — новый путь/цель, снятие задачи или расчистка.

**Подсказки:** опиши переходы операции по событиям, включая потерю цели/исполнителя.
Для готовности группы сравни численность с составом и суммарной боеспособностью;
отдельно продумай, как отличать ожидание от отсутствия прогресса.
**Unit-тесты:** готовность неполного отряда, тайм-аут сбора, срочный отзыв,
потеря цели, выход из затора и невозможность назначить юнита двум группам.

**Готово:** атака начинается собранной группой; тревога у базы вызывает защиту;
потеря преимущества ведёт к отходу, а потеря цели — к разведке её последнего места.
