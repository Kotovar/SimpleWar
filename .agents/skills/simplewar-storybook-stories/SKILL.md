# Истории Storybook для SimpleWar

Создавай истории для указанных объектов и состояний. Разработка игровых механик
остаётся за пользователем: меняй истории, данные примеров и минимальную обвязку.
Не исправляй и не расширяй поведение игры ради истории; найденные дефекты сообщай.

## Подготовка

- Прочитай `AGENTS.md`, `package.json`, конфигурацию Storybook и ближайшие истории.
  Найди реальный компонент/Canvas-рендер и его зависимости через граф кода;
  при неполных результатах читай файлы. Не создавай копию игрового рисунка.
- Проверь установленную версию Storybook. Через Context7 получи документацию
  именно для неё: сначала `resolve-library-id`, затем `query-docs`. Следуй
  существующему формату историй; не переноси примеры из `next` вслепую.
- Если Storybook отсутствует, сообщи об этом. Запрос только на истории не означает
  установку инфраструктуры: подготовь доступные данные/перечень состояний,
  уточни необходимость настройки; не оставляй неработающие импорты в проекте.
  Если настройка уже разрешена, подключи минимальную совместимую конфигурацию
  с учётом React, TypeScript, алиасов и используемого в проекте Vite+.

## Содержание историй

- Переиспользуй расположение, группировку и типизацию существующих историй.
  Названия в интерфейсе и краткие пояснения пиши по-русски; идентификаторы —
  по соглашениям проекта. Сохраняй FSD-границы, не экспортируй истории в runtime API.
- Начни с обычного состояния и добавь только применимые варианты: владелец,
  выделение, повреждение, потраченные действия, недоступность, масштаб, туман.
  Не создавай декартово произведение всех параметров и вымышленные состояния.
- Используй args/controls для независимых параметров. Выделяй отдельной историей
  значимый визуальный случай, который нужно быстро открыть и сравнить.
  Для запроса «все юниты/здания» проверь полноту по реальной конфигурации типов.
- Данные минимальны, типизированы и детерминированы. Не маскируй несовместимость
  через `any`, двойное приведение или отключение проверки типов.
- Canvas показывай через реальный рендер с минимальной обвязкой: размеры, фон,
  DPR и перерисовка при изменении controls. Отменяй анимацию и подписки при размонтировании.
  Не запускай целую партию или ход ИИ ради показа одного объекта.
- Подключай реальные стили/ассеты/шрифты. Подменяй только внешнее окружение,
  не тестируемую отрисовку; не добавляй новый addon ради одного простого примера.

## Изоляция и проверки

- Предпочитай передачу данных в существующий рендер. Если нужен store, используй
  имеющийся способ изоляции; не меняй глобальное состояние на уровне импорта.
  Учти одновременный показ нескольких историй в Docs: сброс общего store перед
  одной историей не изолирует её от соседней. Если изоляция требует переделки игры,
  сообщи границу и согласуй её отдельно, не скрывай конфликт.
- После истории не остаются таймеры, обработчики, подписки, записи в сохранениях
  и изменённые singleton-данные. Переключение историй и повторное открытие стабильны.
- Для интерактивного компонента добавляй play-проверку только полезного поведения
  пользователя через поддерживаемые текущей версией средства. Статичному рисунку
  достаточно просмотра; не подменяй проверку Canvas подсчётом вызовов рисования.
- Выполни проверки кода из `AGENTS.md` и сборку Storybook фактической командой
  проекта. Убедись, что новые истории обнаружены. Открой их в браузере: проверь
  controls, переключение, Docs при его наличии, ассеты, ошибки консоли и заявленные
  размеры. Успешная сборка сама по себе не подтверждает правильность картинки.
- В отчёте: созданные истории/состояния, команды и результаты, что проверено
  в браузере и что осталось непроверенным. Не заявляй визуальную проверку без запуска.
