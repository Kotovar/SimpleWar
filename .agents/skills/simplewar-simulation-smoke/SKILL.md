# Smoke-симуляции SimpleWar

Создай или переиспользуй небольшой воспроизводимый прогон реального игрового кода,
запусти его и отчитайся по наблюдениям. Не исправляй механику или баланс без запроса.
Это проверка сценария и сбор данных, а не доказательство качества ИИ или всех карт.

## Подготовка

- Прочитай `AGENTS.md`, `package.json`, доступные тесты/скрипты и реализацию сценария.
  Ищи через граф кода, проверив путь индекса; при неполных результатах читай файлы.
  Проследи инициализацию, игровой цикл, события и завершение асинхронных действий.
- Используй существующий раннер и реальные функции. Не создавай отдельный движок,
  универсальный стенд или новую зависимость ради одного прогона. Для headless-сценария
  достаточно небольшого файла в существующем тестовом окружении; браузер нужен,
  если предмет проверки зависит от UI или браузерного жизненного цикла.
- Зафиксируй сценарий: размер карты, список сидов, настройки, число ходов,
  поведение игрока, метрики и лимит времени/действий. Соблюдай значения из запроса.
  Если их нет, используй текущие настройки игры, 10 полных раундов для ИИ
  или сиды 0–19 для карт; явно укажи эти допущения. Запускай только нужный сценарий.
- Полный раунд по умолчанию — ход игрока и ответ ИИ. Считай завершённые раунды,
  не подменяй их значением счётчика или числом вызовов `endTurn`.
- Фиксируй все источники случайности, влияющие на сценарий, а не только сид карты.
  Если полной воспроизводимости нет, укажи оставшиеся источники. Между прогонами
  сбрасывай все задействованные хранилища, подписки, таймеры и подмены окружения;
  не полагайся на название `resetStore` без проверки его реализации.

## Ходы и решения ИИ

- Найди актуальные точки запуска. Ориентиры: `src/widgets/start-game/initializeGame.ts`,
  `src/app/game/ai/aiTurn.ts`, `src/features/game-loop`, `src/entities/games/model`.
  Проверяй их реализацию: прямое переключение хода в store может обходить игровые эффекты.
- По умолчанию игрок пропускает ход штатным действием; обозначь это в отчёте.
  Не управляй ИИ вручную и не подменяй его решения, экономику, бой или поиск пути.
- Дожидайся завершения ИИ и связанных эффектов через фактический механизм игры,
  а не произвольную задержку. Ограничь ожидание, число действий и общее время.
- Записывай по каждому ходу: сторону, выполненные действия, цели/координаты,
  ресурсы до/после и существенные изменения юнитов/построек. Используй существующие
  события/логи; если их нет, снимай состояние до/после и называй это изменениями
  состояния, а не полным журналом решений. Причину выбора сообщай только если
  её действительно предоставляет ИИ; предположения помечай отдельно.
- Проверяй продвижение цикла, отсутствие исключений и применимые инварианты
  из кода/документации, например допустимость координат и расходов ресурсов.
  Бездействие ИИ фиксируй как наблюдение, если оно не нарушает установленный контракт.
- При победе остановись штатно и укажи причину и фактическое число раундов.
  Зависание/таймаут — незавершённый прогон, а не успешные 10 ходов.

## Карты по сидам

- Разделяй сырую генерацию (`src/entities/maps/model/generateMap.ts`) и карту после
  подготовки стартовых зон. Для оценки играбельности используй реальный путь
  инициализации; записывай исходный и фактически принятый сид, повторы и отказы.
  Не исключай неудачные сиды из статистики молча.
- Для каждого сида измеряй только нужные метрики. Базовый набор: число и доля
  проходимых клеток, число компонент связности, доля крупнейшей компоненты среди
  проходимых клеток, количество и доля клеток золота и леса среди всех клеток.
  Для пустого множества укажи `N/A`, не дели на ноль.
- Связность считай по реальным правилам движения: соседство, диагонали, срезание
  углов и препятствия. Переиспользуй игровые правила; укажи, учитывались ли юниты
  и здания. Доля проходимых клеток сама по себе не доказывает связность.
- Если есть стартовые позиции, проверь путь между ними и доступность ресурсов
  для каждой стороны. Для непроходимого ресурса считай путь к допустимой позиции
  добычи по игровым правилам, а не к клетке ресурса. Недоступность отмечай отдельно.
  Для распределения используй расстояния от стартов и доступное количество;
  для сырой карты без стартов достаточно долей по одинаковым секторам.
- Сохрани строки по каждому сиду и агрегаты: число успехов/отказов, минимум,
  медиану, максимум выбранных метрик и сиды крайних случаев. Сравнивай разные
  настройки на одинаковом наборе сидов. Не объявляй дисбаланс дефектом без критерия.

## Проверка и результат

- Оставь запускаемый файл и точную команду повторения. Для данных используй простой
  JSON/CSV в указанном пользователем месте, иначе во временном каталоге; не добавляй
  большие журналы в репозиторий. Запиши настройки, сиды и версию кода/наличие diff.
- Прогон должен содержать проверки, которые падают при нарушении установленного
  контракта. Статистика баланса без согласованных порогов остаётся наблюдением.
  Не назначай произвольные пороги и не подгоняй их под полученные результаты.
- Запусти созданный сценарий без watch. Проверь фактическое число выполненных
  раундов/сидов. После добавления кода выполни проверки из `AGENTS.md`.
- Отчёт на русском: команда и параметры, запрошенный/выполненный объём, passed/failed
  или причина остановки, компактная таблица действий/метрик, пути к данным,
  проблемные сиды и ограничения. Отделяй ошибки запуска, нарушения инвариантов
  и гипотезы о балансе. Не называй headless-прогон проверкой UI.
