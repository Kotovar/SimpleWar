# Актуализация документации по коду

Обновляй описание фактически реализованного поведения. Не меняй код, баланс
или согласованный план, чтобы устранить расхождение с документацией.

- Прочитай `AGENTS.md`, указанный diff/файлы и относящиеся к ним документы.
  Если запрос относится к текущим изменениям, учти staged и unstaged diff,
  а также относящиеся к задаче новые файлы. Не делай аудит всего проекта без запроса.
- Через граф кода найди изменённые функции, вызовы и реально используемый путь;
  при неполном индексе читай исходники. Константа, тип, заглушка или недостижимая
  ветка не доказывают наличие механики. Проверяй использование значений.
- Сопоставь изменения с документами: `docs/README.md` — обзор состояния,
  `mechanics.md` — правила, `units.md`/`buildings.md` — состав и характеристики,
  `development.md`/`unit-testing.md` — фактические команды и проверки.
  Обновляй только затронутые разделы, сохраняя принятый краткий русский стиль.
- Отделяй подтверждённое по коду от проверенного запуском. Если для вывода нужно
  исполнение, используй имеющуюся проверку либо обозначь ограничение. Не приписывай
  браузерную проверку, полную поддержку или баланс по одному unit-тесту.
- Roadmap и предложения описывают намерения. Не вычёркивай требование из-за
  отсутствия реализации и не закрепляй баг как новое правило. Расхождения вынеси
  в отчёт: «план → код → что требует решения», не принимай решение за пользователя.
- Чекбокс этапа закрывай только если это входит в запрос и есть подтверждение
  всех его критериев/проверок. Частичную реализацию отмечай как частичную;
  не назначай этап до/после MVP и не меняй зависимости самостоятельно.
- Числа, команды, ограничения и названия сверяй с текущим источником. Сохраняй
  один основной раздел для правила, в других местах давай ссылки; устраняй
  противоречия только в пределах подтверждённого изменения.
- Проверь diff, относительные ссылки и якоря, соответствие таблиц источникам,
  отсутствие неподтверждённых отметок «готово». Выполни существующие проверки
  документации, если они настроены. Для правок только Markdown не запускай
  игровой набор без требования проекта или необходимости проверить утверждение.
- Не добавляй историю работы агента и придуманные результаты запусков в справочники.
  Сохраняй посторонние изменения, не делай stage/commit.

Отчёт: обновлённые документы и смысл изменений, выполненные проверки,
найденные расхождения с планом и факты, которые не удалось подтвердить.
