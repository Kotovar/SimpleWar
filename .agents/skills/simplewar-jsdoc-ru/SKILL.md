# Краткий JSDoc на русском

Документируй только функции, которые указал пользователь, либо функции в явно
указанных файлах. Если цели не указаны, попроси имена функций или пути.

- Прочитай `AGENTS.md`, реализацию целевых функций и необходимый контекст вызовов.
  Описывай фактическое поведение; не угадывай назначение по имени.
- Меняй только JSDoc. Обновляй существующий блок, не добавляй второй.
  Сохраняй важные сведения о контракте и существующие служебные теги.
- Первая строка — одно короткое предложение на русском с глаголом в настоящем
  времени: «Возвращает…», «Проверяет…», «Обновляет…». Объясни назначение,
  не пересказывай алгоритм и не начинай с «Эта функция».
- После описания оставь одну пустую строку перед тегами. Для каждого аргумента
  добавь `@param имя - Краткое назначение.` в порядке сигнатуры.
  Имена сохраняй как в коде; в TypeScript не дублируй типы в фигурных скобках.
  Для деструктурированного аргумента используй имя объекта в JSDoc и записи
  `@param имя.поле`, не меняя сигнатуру ради комментария.
- Если есть возвращаемое значение, добавь `@returns Краткий смысл результата.`.
  Для `void` и `Promise<void>` тег не нужен. Для Promise описывай итоговое значение.
- Указывай единицы измерения, изменение входных данных, значимые `null`/`undefined`
  и условия исключений, только если это часть контракта. Для исключений используй
  `@throws`. Не добавляй примеры, историю изменений или подробности реализации
  без запроса.
- Все описания начинай с заглавной буквы и заканчивай точкой. Без аргументов
  и результата достаточно однострочного `/** Проверяет состояние игры. */`.

Единый формат:

```ts
/**
 * Возвращает расстояние между клетками карты.
 *
 * @param from - Начальная клетка.
 * @param to - Конечная клетка.
 * @returns Расстояние в клетках.
 */
```

После правок проверь соответствие комментариев сигнатурам и реализации,
убедись, что исполняемый код не изменился, и выполни проверки из `AGENTS.md`.
В отчёте кратко перечисли документированные функции и результат проверок.
