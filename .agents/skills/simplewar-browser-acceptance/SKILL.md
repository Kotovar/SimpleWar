# Браузерная приёмка SimpleWar

Проверь указанный сценарий через реальный интерфейс. Результат — наблюдения,
воспроизведение дефектов и доказательства. Не исправляй игру без отдельного запроса.

- Прочитай `AGENTS.md`, команды запуска и описание нужной механики. Определи
  исходные условия, шаги и ожидаемый результат по запросу и принятому контракту.
  Нереализованное требование roadmap отмечай отдельно от поломки существующего.
- Проверь адрес и версию запущенного приложения: сервер должен обслуживать этот
  checkout. Переиспользуй подходящий сервер; не останавливай чужие процессы.
  Используй доступные браузерные инструменты, не устанавливай новый стек без нужды.
- Работай в отдельном браузерном контексте/профиле, чтобы не затронуть сохранения
  пользователя. Фиксируй браузер, viewport, DPR, сид, настройки и версию кода/diff.
  Если размеры не заданы, начни с 1280×720; добавляй планшет/другие размеры,
  когда проверяемое поведение зависит от адаптивности.
- Выполняй пользовательские действия кликами и клавиатурой. Подготовка сложной
  сцены через существующую фикстуру допустима, но явно перечисли обходы; нельзя
  засчитать старт партии или действие, которое было заменено прямым изменением store.
- Для Canvas учитывай его текущий размер, DPR, камеру и масштаб. Проверяй,
  что клик действительно выбрал нужную клетку/объект. Если координаты неясны,
  исследуй путь преобразования через граф кода, затем исходники.
- После каждого значимого действия проверяй видимый результат: выделение,
  ресурсы, доступность команд, смену стороны, исход или сообщения. Чтение store
  помогает диагностике, но не заменяет проверку пользовательского результата.
- Жди наблюдаемого условия с ограниченным таймаутом, а не случайной задержки.
  Собирай ошибки консоли и неудачные запросы; связывай их с конкретным шагом.
  Ошибка окружения и дефект игры — разные результаты.
- Для сбоя сохрани минимальные шаги, ожидаемое/фактическое, сид и снимок экрана.
  По возможности повтори с чистого состояния. Не делай бесконечных повторов:
  если повтор не подтвердился, сообщи о нестабильности и числе попыток.
- Проверяй только заявленный объём. Доступность/видимость интерфейса, туман,
  клавиатуру и сохранения проверяй там, где их касается сценарий; не превращай
  одну проверку в аудит всей игры. Полную приёмку оценивай по указанному этапу.
- Артефакты клади в указанное место, иначе в каталог `/tmp` этой проверки.
  Закрой свои контексты и останови только запущенные тобой временные процессы.
  Кодовые проверки нужны при добавлении кода согласно `AGENTS.md`.

Отчёт на русском: окружение и команда запуска, таблица «шаг → ожидание → факт →
passed/failed/not run», дефекты со ссылками на артефакты, непроверенные границы.
Без доступного браузера обозначь проверку как невыполненную; build и headless
симуляция не подтверждают работу интерфейса.
