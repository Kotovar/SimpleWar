# Регрессионный тест по багу

Результат — минимальный запускаемый тест правильного поведения, который выявляет
указанный дефект. Не исправляй production-код и не меняй игровые правила.

- Прочитай `AGENTS.md`, описание бага и текущий diff. Зафиксируй входные условия,
  наблюдаемый результат и ожидаемое поведение; источник ожидания — запрос,
  согласованный контракт или подтверждённое прежнее поведение, не текущий баг.
  При неоднозначности уточни ожидание, продолжая независимое воспроизведение.
- Проследи реальный путь от действия до результата через граф кода и исходники,
  включая вызывающие функции и зависимости. Сократи воспроизведение, сохранив
  причину сбоя; не выбирай удобную функцию, если она обходит проблемный путь.
- Используй существующий раннер и минимальный достаточный уровень: unit для
  расчёта, интеграционный тест для связки store/событий, браузер для Canvas/DOM
  и браузерных ограничений. Для unit-теста прочитай
  [simplewar-unit-tests](../simplewar-unit-tests/SKILL.md), для браузерного сценария —
  [simplewar-browser-acceptance](../simplewar-browser-acceptance/SKILL.md).
- Импортируй реальный код, фиксируй случайность/время при необходимости, изолируй
  хранилища и очищай подписки. Подменяй только внешние зависимости; не копируй
  алгоритм и не мокай источник дефекта. Не добавляй абстракции или новый раннер
  ради одного случая, не меняй production API ради удобства теста.
- Напиши один тест с конкретным ожидаемым результатом. Подготовь остальные
  условия валидными, чтобы проверка не останавливалась на постороннем запрете.
  Не проверяй текст сообщения, если он не часть контракта.
- Запусти тест и докажи, что он дошёл до нужного assertion и упал именно из-за
  расхождения поведения. Ошибка импорта, таймаут подготовки или отсутствие тестов
  не считаются воспроизведением. При необходимости добавь один соседний контрольный
  случай, показывающий, что стенд способен пройти исправный сценарий.
- Не используй `.skip`, `.only`, expected-failure или ожидание ошибочного результата
  для зелёного запуска. Намеренно падающий тест — допустимый результат этой задачи;
  явно предупреди о его влиянии на общий набор. Не коммить и не исправляй игру.
- Если тест прошёл, проверь исходные условия и актуальность бага. Не создавай
  искусственный сбой: сообщи «не воспроизведено» либо «защитный тест проходит».
  Если текущий код уже исправлен, не заявляй проверку старой версии без её запуска.
- Выполни проверки из `AGENTS.md`, отдели ожидаемое падение нового теста от других
  проблем. Сохрани пользовательские изменения и оставь точную команду повторения.

Отчёт: файл теста, сценарий, ожидание/факт, команда, причина падения и результаты
остальных проверок. После исправления пользователем этот же тест должен проверять
правильный результат без переписывания ожиданий; его будущий успех не обещай.
